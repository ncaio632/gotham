# バックログと検証対応 — gotham

[英語完全版](delivery-validation.en.md)の要約です。製品検証はすべて**計画・未実行**です。

| 順序 | 作業と受入条件 |
| --- | --- |
| B1 | 用語、役割、版規則、架空資料の制約を明確にする。 |
| B2、B1後 | 帰属と履歴を維持し、参照解決・証拠審査・矛盾保持を実装する。 |
| B3、B2後 | 担当必須、提案と確認済み約束の区別、無権限の期限・約束拒否を実装する。 |
| B4、B3後 | 主張参照付き文章、不確実性、過去の失敗、実行可能な差戻しを実装する。 |
| B5、B4後 | 正確な版の原子的比較、自己審査拒否、編集による承認失効、送信なしを実装する。 |
| B6、B5後 | 架空手順を実行し、独立編集レビューと明示的な未解決項目を記録する。 |

B5のために送信アダプターを追加しません。将来の送信は別の契約と認可が必要です。

| 要件 | 計画する検証 |
| --- | --- |
| G01 | 不足は確認依頼し、申告・履歴の帰属を保つ。 |
| G02 | 証拠・確認担当がなければverifiedにしない。 |
| G03 | 未審査・不在・矛盾資料で断定を止め、矛盾を保存する。 |
| G04 | 失敗した連絡方法の無理由な反復を差戻す。 |
| G05 | 担当不在・提案段階の約束では審査や承認を止める。 |
| G06 | 誇張や責任暗示は人が修正を要求する。 |
| G07 | 自己審査、旧版、同時編集を承認しない。 |
| G08 | 編集で承認失効、外部送信ゼロ、解決を推定しない。 |
| G09 | 架空例のみ、私的本文をログに含めない。 |

[Schema](../contracts/case-review.schema.json)をDraft 2020-12で検証します。[正常例](../examples/review.valid.json)は別役割による同じ版の承認です。[構造不正例](../examples/review.invalid-schema.json)はverifiedの`claims[1].evidence_refs`を欠落させます。[意味不正例](../examples/review.invalid-semantic.json)は構造適合ですが、作者による旧版承認なので`SELF_REVIEW`と`STALE_REVIEW`で拒否します。

Schemaは真偽、担当権限、版の一致、口調を確認できません。アプリは参照・約束・審査方針、人は忠実さと言葉遣いを確認します。将来の証跡にはID、実装・入力・ケース・下書き版、環境、期待値・観測値、審査役、`not_run/pass/fail/blocked`が必要です。文書検証から顧客満足、所要時間、本番適性を主張できません。実運用には権限・保持・エスカレーション・送信境界の別審査が必要です。
