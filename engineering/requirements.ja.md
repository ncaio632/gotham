# 要件 — gotham

[英語完全版](requirements.en.md)の実装向け要約です。[既存の公開フロー](../docs/architecture.ja.md)を具体化した提案で、自動送信、チケット連携、実測SLAはありません。

目的は、申告と事実を分け、過去の連絡と証拠を確認し、担当を決め、人が承認した回答下書きを作ることです。送信、返金、顧客記録変更、法的責任判断は対象外です。申告は申告の存在を示すもので、事件自体の証明ではありません。内部記録がないことも申告の誤りを意味しません。

| ID | 提案する必須動作 |
| --- | --- |
| G01 | 架空参照、チャネル、帰属を明示した要約、過去の連絡を記録する。不足は確認し、日時や出来事を捏造しない。 |
| G02 | 主張を`reported/verified/disputed/unknown`に分類する。verifiedには審査済み証拠と確認担当が必要。 |
| G03 | 証拠の参照・審査状態を主張に関連付ける。承認済み資料の全内容を真実扱いせず、矛盾は調査する。 |
| G04 | 過去の連絡結果を読み、失敗した手段の繰返しには理由または担当付き代案を要求する。 |
| G05 | 審査前に責任担当を1つ決める。約束には確認済み担当・期限表現・証拠が必要。不明なら承認を止める。 |
| G06 | 事実を述べる文を主張参照に結び、未解決申告は帰属を明示する。共感を責任認定や成果保証にしない。 |
| G07 | ケース版と下書き版の正確な組を人が承認する。提案デモでは作者と別の審査役を要求する。 |
| G08 | 承認は送信しない。編集で承認を無効化し、別証拠なく送信済み・解決済みと呼ばない。 |
| G09 | 公開例と技術証跡は架空のみ。本文をログに入れず、機密情報があれば公開を止める。 |

画面では申告と確認事実、過去の連絡、欠落、担当、約束を下書きの横に表示します。審査対象の本文と版を明示し、`MISSING_EVIDENCE`、`REPEATED_FAILED_CONTACT`、`UNCONFIRMED_COMMITMENT`、`STALE_REVIEW`で差戻しできます。事実が未確定でも、不確実性を明示した受領の回答は可能です。下書き準備の完了は問題解決を意味しません。

実装前に情報源、証拠鮮度、権限、エスカレーション、保持、機微案件の方針を決めます。補償権限、送信チャネル、送信認可は未定です。
